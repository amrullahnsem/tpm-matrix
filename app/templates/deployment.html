Recommended for Windows Server (Hume Cement local network): Running as a native Windows Service ensures the application automatically boots with Windows, runs silently in the background, and auto-restarts upon crashes.

Method A: One-Command Service via NSSM (Non-Sucking Service Manager)

Open an elevated PowerShell (Run as Administrator) on your production Windows server and run: 

# 1. Navigate to the project root
cd C:\eflow-tpm-matrix

# 2. Download NSSM if not already installed (via winget or choco)
winget install NSSM.NSSM -e --silent

# 3. Create and configure Windows Service
nssm install EflowTpmMatrix (Get-Command python.exe).Source "run.py --host 0.0.0.0 --port 8000 --workers 4"
nssm set EflowTpmMatrix AppDirectory "C:\eflow-tpm-matrix"
nssm set EflowTpmMatrix DisplayName "Hume EFLOW TPM Matrix System"
nssm set EflowTpmMatrix Description "Crusher Division Maintenance Competency Matrix Web Application"
nssm set EflowTpmMatrix Start SERVICE_AUTO_START
nssm set EflowTpmMatrix AppStdout "C:\eflow-tpm-matrix\data\service_out.log"
nssm set EflowTpmMatrix AppStderr "C:\eflow-tpm-matrix\data\service_err.log"

# 4. Start the service
Start-Service EflowTpmMatrix

# 5. Verify service is running
Get-Service EflowTpmMatrix

Method B: Native Windows Task Scheduler (No Extra Software Required)

If third-party tools are restricted, register an auto-start task that triggers on system startup: 

# Run in Administrator PowerShell to create an auto-start background task:
$Action = New-ScheduledTaskAction -Execute (Get-Command python.exe).Source -Argument "run.py --host 0.0.0.0 --port 8000 --workers 4" -WorkingDirectory "C:\eflow-tpm-matrix"
$Trigger = New-ScheduledTaskTrigger -AtStartup
$Principal = New-ScheduledTaskPrincipal -UserId "SYSTEM" -LogonType ServiceAccount -RunLevel Highest
Register-ScheduledTask -TaskName "EflowTpmMatrix" -Action $Action -Trigger $Trigger -Principal $Principal

# Start the task now
Start-ScheduledTask -TaskName "EflowTpmMatrix"

Windows Firewall Configuration

Allow other computers on the Hume local network to access the web application on port 8000: 

New-NetFirewallRule -DisplayName "Hume EFLOW TPM Matrix (Port 8000)" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow
Docker Container Deployment: Fully self-contained container with healthcheck probe on /healthz and isolated dependencies.

Option 1: Using Docker Compose (Single Command)

# In project directory:
docker-compose up -d --build

# View real-time container logs:
docker-compose logs -f app

# Stop the container:
docker-compose down

Option 2: Using Raw Docker CLI

# 1. Build the production image:
docker build -t eflow-tpm-matrix:latest .

# 2. Run container with data volume mount for database persistence:
docker run -d \
  --name eflow-tpm-matrix \
  --restart unless-stopped \
  -p 8000:8000 \
  -e HOST=0.0.0.0 \
  -e PORT=8000 \
  -e WORKERS=4 \
  -v tpm_matrix_data:/app/data \
  eflow-tpm-matrix:latest

# 3. Check health status:
{% raw %}docker inspect --format='{{json .State.Health}}' eflow-tpm-matrix{% endraw %}
Linux / Enterprise Cloud: Recommended architecture uses Systemd to manage Uvicorn processes and Nginx as reverse proxy with SSL termination.

1. Systemd Service File: /etc/systemd/system/tpm-matrix.service

[Unit]
Description=Hume EFLOW TPM Competency Matrix Service
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/var/www/eflow-tpm-matrix
Environment="PATH=/var/www/eflow-tpm-matrix/.venv/bin:/usr/bin"
Environment="HOST=127.0.0.1"
Environment="PORT=8000"
Environment="WORKERS=4"
ExecStart=/var/www/eflow-tpm-matrix/.venv/bin/python run.py --no-reload
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target

2. Nginx Reverse Proxy Config: /etc/nginx/sites-available/tpm-matrix.conf

server {
    listen 80;
    server_name tpm.humecement.com.my;

    client_max_body_size 20M;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /healthz {
        proxy_pass http://127.0.0.1:8000/healthz;
        access_log off;
    }
}
Environment variables can be provided via a .env file in the project root or passed into the container/service environment.
Variable Default Production Recommended Description
HOST 127.0.0.1 0.0.0.0 IP address to bind the web server to (use 0.0.0.0 for LAN access)
PORT 8000 8000 or 80 HTTP listening port
WORKERS 1 4 (2 × CPU cores + 1) Number of concurrent Uvicorn worker processes
RELOAD false false Auto-reload on code change (must be false in production)
LOG_LEVEL info warning or info Server logging verbosity
